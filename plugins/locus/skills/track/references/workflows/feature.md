# Feature Workflow

Use for a new or materially expanded capability.

## Phases

| Phase     | Reference                              | Purpose                                            |
| --------- | -------------------------------------- | -------------------------------------------------- |
| Ideate    | [ideate.md](../phases/ideate.md)       | Refine one outcome; persist it only when resumable |
| Design    | [design.md](../phases/design.md)       | Approve the design at proportional depth           |
| Plan      | [plan.md](../phases/plan.md)           | Approve executable implementation steps            |
| Implement | [implement.md](../phases/implement.md) | Deliver the smallest approved change               |
| Review    | [review.md](../phases/review.md)       | Review through the authorized delivery path        |
| Complete  | [complete.md](../phases/complete.md)   | Reconcile and verify the integrated result         |

## Rules

Phase decisions and approval gates are mandatory; separate artifacts are
proportional. When repository policy and explicit human intent permit bounded,
low-risk work, record Design and Plan inline. Do not create an Issue,
specification, plan, branch, worktree, or pull request solely to represent a
phase. Resume at the first incomplete phase. A GitHub Project is optional; use
one only when an owning Project exists.
